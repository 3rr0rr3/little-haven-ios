# Physical-phone startup report and bounded hotel composition (v45)

The user's actual v44.0 (49) report on iPhone 17 Pro Max / iOS 27.0 completes motel creation, world and management preparation, checkpoint writing and hotel state assignment. Its last stage is `hotel_body_begin`. It does not reach `hotel_content_constructed`, office actor creation, map construction or renderer drawing. This scopes the failure to hotel view construction, but does not provide an exception or prove a specific SwiftUI defect.

The v44 outer `AnyView(hotelContent)` still eagerly constructed the full deeply nested screen and modifier value before erasing its type. V45 replaces that single long composition with six separate, non-inlined functions returning AnyView: chrome, startup tasks, movement tasks, simulation tasks, observation and sheets. Each function receives an already erased value. Modifier order, state bindings, cancellation IDs and action closures remain unchanged. A small child View defers the active screen's construction to its own body evaluation; another child boundary defers the active map. These boundaries reduce the nested value and generic metadata constructed on one call stack in optimized builds. This is a targeted compatibility candidate, not confirmation of the exact physical-phone exception.

The local startup report now records completion of each group and active screen/map construction. If the phone still stops, its copied report can distinguish the specific group from screen and renderer entry. The artwork, model, save schema, collision rules and progression are unchanged. No saves are reset.

Native validation includes actual optimized Release builds using ordinary title/Continue/wake navigation with no app launch arguments, in standard and fullscreen modes, plus checkpoint reopening. CI also reads the app container's real startup record and requires every construction boundary, map creation, compatible reception drawing and `hotel_stable`, with the pending flag cleared. The simulator is iOS 18.5; physical iOS 27 confirmation remains outstanding.
